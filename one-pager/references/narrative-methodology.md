# one-pager 叙事方法论 · Narrative Methodology v1.3

**目录**：0 三层协议总览 · 1 L1 论证层 · 2 L2 段落层（含 Owner 标签与数据溯源铁律）· 3 L3 句子层 · 4 0→1 生成协议 · 5 100→1 浓缩协议（5.1 五步法 / 5.2 三叉路由 / 5.3 禁令 / 5.4 Proposal 五段式 / 5.5 Book Memo 七段式 / 5.6 Insight Page 七段式）· 6 质检门 Q1-Q9 · 7 与视觉层交接 · 8 来源谱系表

> **角色**：你是 one-pager skill 的叙事决策层。视觉风格（长什么样）由 style-system.md 裁决；内容叙事（说什么、怎么说、怎么删）完全由本文件裁决。生成任何一页纸之前，先判断任务类型（0→1 生成 / 100→1 浓缩），走对应协议，再进入视觉层。
>
> **来源谱系**：主体为亚马逊叙事文化（AWS Doc Writing Guidance、6-pager、PR/FAQ、Working Backwards）；100→1 浓缩侧由 MBB 咨询方法论补位（金字塔原理归纳法、80/20、Action Title、水平逻辑、电梯测试、So What 测试），逐条标注出处见第 8 节。金字塔原理同时出现在 AWS 官方幻灯片中，视为同源。三个场景分叉各有经典房屋模式基底：决策行动以用户真实黄金样例《Shortening GCR Program Application Leading Time (Pilot)》（AWS GCR，2024-10）为模板（5.4 节）；学习复述以 Adler《How to Read a Book》分析阅读规则 × Derek Sivers 书目备忘录为模板（5.5 节）；信服洞察以 Zelazny《Say It With Charts》× FT 数据新闻为模板（5.6 节）。
>
> **组织原则**：
> - **MECE**：三层协议各管一事且互不重叠——论证层管主张的结构、段落层管信息的覆盖、句子层管语言的纪律；浓缩场景按"读者下一步动作"分叉，互斥且穷尽（学习复述 / 决策行动 / 信服洞察）。
> - **3-7 原则**：任何并列信息组 3-7 条；浓缩分组 3-7 组；单句目标 ≤30 词（中文 ≤35 字，硬上限 40 词）。
>
> **一句话总纲**：一页纸是论证工具，不是信息容器。一页约束约束的是论证，不是证据——证据全部降级进附页，且每个数据可溯源。

## 0 · 三层协议总览

对应 AWS 幻灯片 FRAMEWORK / SENTENCE 的分层意识，展开为三层：

| 层 | 管什么 | 核心武器 | 出处 |
|---|---|---|---|
| L1 论证层 | 主张如何组织 | 金字塔原理：结论先行、以上统下、MECE、Rule of Three | Minto / AWS |
| L2 段落层 | 信息覆盖哪些维度 | 叙事五维度 What/Who/Why/How/FAQ+Appendix | AWS |
| L3 句子层 | 语言纪律 | 五条句法 + 反 bullet | AWS |
| QC 质检层 | 交付前验收 | 水平逻辑、So What、电梯测试、weasel 扫描 | MBB |

执行顺序：任何任务都按 L1→L2→L3→QC，禁止跳层（先想句子的往往写不出主张）。

## 1 · L1 论证层：金字塔结构

**四条原则**（违反任何一条，论证即散架）：

1. **结论先行**：第一段第一句就是核心主张。读者只读第一句也能带走 80% 的信息。
2. **以上统下**：上层是下层的结论，下层是上层的支撑。任何一个信息块被删掉，其上层结论必须还能被其余支撑撑住，否则结论改写。
3. **归类分组（MECE）**：同层信息组之间互斥（无重叠）、合并起来穷尽（无遗漏）。允许"其他"组存在，但不得超过总信息量的 10%。
4. **逻辑递进 + Rule of Three**：并列信息 3-7 条，禁止 2 条（不构成组，改为对照句）和 8+ 条（超认知负荷，重新归纳）。

**开场用 SCQ**（Situation-Complication-Question）：

| 要素 | 内容 | 约束 |
|---|---|---|
| S 情境 | 读者认同的背景事实 | ≤2 句，必须是读者已知的 |
| C 冲突 | 打破平衡的变化/问题/机会 | ≤2 句，制造张力 |
| Q 问题 | 由此引出的核心问题 | 1 句，或直接隐含在 C 中 |
| A 答案 | 你的主张（=BLUF 结论） | SCQ 总长 ≤1/4 页 |

**Non-Goals 必写**：明确声明本页不解决什么。边界即论证的一部分——没有 Non-Goals 的主张会被读者的"那为什么不…"拖垮。

## 2 · L2 段落层：叙事五维度

任何一页纸必须能回答以下五问，缺任何一问都回炉（附页型维度允许降级进附页）：

| # | 维度 | 回答什么 | 一页内的落位 |
|---|---|---|---|
| 1 | What | 本页目的与核心主张 | 首段 BLUF |
| 2 | Who | 背景：读者是谁、利益相关方是谁 | 决定详略与语气，可不显式成段 |
| 3 | Why | 当前问题：为什么是现在、不做的代价 | SCQ 的 C 承载 |
| 4 | How | 建议 + 下一步行动 | 正文主体，行动项必须带 Owner 与时限 |
| 5 | FAQ & Appendix | 反方问题与全部证据 | 正文外：附页 / 折叠区 / 图注 |

**证据降级铁律**（源自亚马逊 6-pager 的正文/附页分工）：数据表、长引文、推导过程、旁支论证，一律降级进附页。正文引用证据时只保留"足以支撑结论的最小数据单元"（如一个百分比、一个对比），并在括号或图注中标注附页锚点。

**Owner 标签与决策旗标**（源自 Amazon 决策文档实践）：正文中的每个建议/行动项必须携带 `(Owner: 角色)` 标签（写角色不写人名，如 BD / PM / Finance）；涉及决策的段落显式标注决策权归属（"seek X's final decision" / "Subject to X's final decision"）。读者读完必须能一句话回答：谁拍板、谁执行、何时交付。

**数据溯源铁律**（适用所有分叉、两种协议）：正文出现的任何数据（数字、比例、金额、时长、排名、日期）必须携带数据锚点 (D1)、(D2)…（全文唯一编号），并在附页**数据溯源表**中有对应行。溯源表五列：锚点 / 数据值 / 来源（系统、文档、访谈、原文位置）/ 时间或版本 / 可复核路径。双向完整性：正文锚点必在表中有行，表中有行必在正文被引用——无主数据行删除。无来源数据三选一：补来源、删数据、显式标注"估计值/待验证"；禁止无源数据伪装成有源数据。验收标准：读者对正文任何一个数字都能在 3 分钟内完成 crosscheck。

## 3 · L3 句子层：句法五纪律 + 反 bullet

**五条纪律**（AWS Writing Tips 原文）：

1. **Use Active Voice（主动语态）**：主语-动词-宾语。"转化率被活动提升了"→"活动把转化率提升了 12%"。禁被动语态，除非动作执行者确实未知且无关。
2. **Own Your Work（Ownership）**：用"我们/我建议"，禁"据了解/大家认为/据悉"。每个主张都有明确的所有者。
3. **Use Positive Statement（肯定句式）**：说"做什么"，不说"不做什么"。例外：Non-Goals 段本身就是否定式，这是其功能。
4. **Use Math & Quantify（数据代形容词）**：任何形容词出现时自问能否换成数字。
   - "用户流失严重" → "30 天留存从 41% 降到 27%"
   - "性能显著提升" → "P99 延迟下降 42ms（-28%）"
5. **Kill Weasel Words（杀模糊词）**：下表左列词出现即回炉，替换为具体数值、范围或直接删除：

| 禁用（weasel words） | 替换为 |
|---|---|
| 几乎所有 / 大部分 / 很多 | 具体比例（"72% 的受访者"） |
| 显著 / 大幅 / 严重 | 具体变化量（"-28%"） |
| 经常 / 频繁 / 有时 | 频次（"每周 3 次"） |
| 大概 / 左右 / 一定程度上 | 明确区间（"35-40ms"）或删除 |
| 据说 / 据了解似乎 | 删除，或补上信源 |

**句长与反 bullet**：

- 单句目标 ≤30 词（中文 ≤35 字），硬上限 40 词（真实 Amazon 文档常态在 30-40 词区间）；超上限先拆分，禁止用分号硬连。
- **正文必须完整句子，禁止 bullet 堆砌论点**（亚马逊 2004 年禁 PPT 的核心理由：bullet 允许作者跳过逻辑飞跃，完整句子逼你补上"因为…所以…"）。bullet 只允许用于：行动项清单、Non-Goals 清单、附页的数据罗列——即"清单性质"内容，论证必须成段。
- **行内编号 [N] 是第三形态**：论证段内需要枚举并列项时，用行内编号（"[1] Skill Development: …… [2] ……"）而非 bullet 换行——保留叙事流完整性，同时给每个论点一个可被附页（解-题映射表）和后文引用的编号锚点。适用于方案列表、行动项列表等需要被引用的枚举场景。

## 4 · 0→1 生成协议（从零构建主张）

适用：没有现成素材，从想法/任务出发写一页纸。

```
Step 1 定读者与动作 → Step 2 Working Backwards 写 PR → Step 3 反方 FAQ 轰炸
→ Step 4 SCQ+A 搭金字塔 → Step 5 五维度填空 → Step 6 句法纪律过稿
```

1. **定读者与动作**：先回答"谁读这一页、读完要做什么决定"。回答不了禁止动笔。
2. **Working Backwards 写 PR**（亚马逊新品方法论）：跳到"这件事成功落地那天"，以发布日视角写一段 100-150 字的新闻稿式描述（问题→现有方案为何不够→新方案→用户得到什么）。这段就是你的 A（答案），写不出说明主张未成型。
3. **反方 FAQ 轰炸**：站在最挑剔的读者角度写 5-8 个最狠的问题（单位经济、风险、依赖、凭什么是你）。回答不了的，要么补论证，要么把限制写进 Non-Goals。所有问答降级进附页。
4. **SCQ+A 搭金字塔**：把 PR 提炼成一句话主张（A），反推 S（什么背景让这个主张有意义）、C（什么变化打破了背景）、Q（什么问题必须回答）。同层按 MECE 归纳成 3-7 组。
5. **五维度填空**：对照第 2 节表格逐项检查，缺项回炉。
6. **句法过稿**：对照第 3 节逐句扫描，weasel word 一律处决。

**迭代纪律**（Jassy 的 30 稿精神）：初稿只为暴露问题，不为交付。写不清楚 = 没想清楚——卡住的段落不是排版问题，是认知缺口，回到 Step 2-3 补论证，禁止用更花的形式掩盖。

## 5 · 100→1 浓缩协议（从素材提炼一页）

适用：已有大量素材（书/长文/文档/纪要/报告），压成一页纸。**浓缩 ≠ 摘要**：摘要是从原文向下删减，浓缩是从事实向上归纳。

### 5.1 浓缩五步法

```
Step 1 80/20 扫描 → Step 2 提炼单句主张 → Step 3 归纳分组
→ Step 4 结论做标题 → Step 5 证据降级 + 双测自检
```

1. **80/20 扫描**（麦肯锡）：第一遍通读只标记三类内容——结论句、硬数据、决策/行动点，其余全部视为可弃。自问"只保留 20%，读者损失什么"，不可损失的部分就是浓缩核心。
2. **提炼单句主张**（电梯测试，麦肯锡）：30 秒内向不了解素材的人讲清"这份材料主张什么"。讲不出 = 没读懂，回 Step 1，禁止带着模糊理解开始排版。
3. **归纳分组**（金字塔归纳法，Minto）：从标记的事实中向上归纳共性结论，形成 3-7 组，组间 MECE。**禁止目录式压缩**（照抄原文章节结构）——那是摘要不是浓缩；原文结构服务于原文篇幅，不服务于一页纸。
4. **结论做标题**（Action Title，麦肯锡一页一观点）：每组的标题写该组的结论，不写该组的主题。"三种增长渠道"是主题（废），"老带新是唯一未被挖掘的增长杠杆"是结论（用）。
5. **证据降级**：每组保留 1-3 个最小数据单元支撑结论（按 L2 数据溯源铁律带 D# 锚点），其余全部进附页；浓缩场景溯源表记原文位置（第几页/第几节），供读者回原文 crosscheck；然后跑第 6 节质检门。

### 5.2 场景分叉（按读者下一步动作路由，MECE 且开放扩展）

路由判定只问一个问题：**读者读完这一页，下一步动作是什么？**

| 读者动作 | 场景 | 浓缩目标 | 分叉要点 |
|---|---|---|---|
| **学习复述** | 书籍 / 长文 / 课程 | 读者能向别人复述核心论点 | 默认采用 5.5 Book Memo 房屋模式；主张=作者核心论点；金句至多保留 3 条且只做装饰锚点；附页放论据地图（哪章支撑哪个结论） |
| **决策行动** | 工作文档 / 会议纪要 / 邮件串 / Proposal 审批 | 读者做出决定并知道下一步 | 默认采用 5.4 Proposal 五段式房屋模式；单方案推荐（不列选项对比）；删除全部过程性叙述（讨论经过、寒暄、重复发言）；行动项带 Owner 标签+时限 |
| **信服洞察** | 调研报告 / 数据分析 | 读者认同一个反直觉结论 | 默认采用 5.6 Insight Page 房屋模式；SCQ 开场；主张=最反直觉的那条洞察；一图一结论（图表的标题写结论不写指标名）；数据代形容词严格执行；方法论与样本细节进附页 |

**扩展新场景**：遇到表外素材（如竞品分析、复盘、个人总结），按"读者下一步动作"归入三叉之一；三叉覆盖不了的（动作既非学非决非信），先质疑是否该做成一页纸。

**标题传统按场景分治**：文档级标题两传统一致（动作式或结论式，可带范围限定词）；分歧在段落级小节标题——决策行动分叉用**功能性标题**（Purpose / What we observed / Proposed solution / Next Steps 做路标，结论压在首段 Purpose，BLUF 承担结论功能）；学习复述与信服洞察分叉用 **Action Title**（标题即结论，必须过 Q2 水平逻辑测试）。同一文档内不混用两种传统。

### 5.3 浓缩禁令

- 禁止保留原文的完整性执念：浓缩的损失是功能，不是缺陷。
- 禁止用"篇幅不够"当理由堆 bullet——放不下是归纳没做完，回 Step 3。
- 禁止中性转述：每一段都要有立场（So What 测试不过的段落删除或改写）。

### 5.4 决策行动分叉 · Proposal 五段式房屋模式

> 蒸馏自黄金样例《Shortening GCR Program Application Leading Time (Pilot)》（AWS GCR，2024-10，匿名）——Amazon 决策文档传统的完整落地。决策行动分叉（尤其 Proposal/审批类一页纸）默认采用此骨架。

**五段式骨架与公式**：

| # | 段落 | 公式 |
|---|---|---|
| 0 | 标题行 | 动作式标题 + 范围限定词（如 "(Pilot)"）+ 日期；不署名（团队所有制） |
| 1 | Purpose | 两句完成 BLUF：① 文档目标 + 决策旗标（seek 谁的 final decision）② 量化目标 from→to 带阶段拆解 + 战略理由 + 附页指针 |
| 2 | What we observed | 证据来源 + 一句话诊断 + (a)-(e) 关键因子（3-7 条、MECE），关键因子内嵌带出处的硬数据 |
| 3 | Proposed solution | 按流程阶段分组（不按主题），每组头部带量化预期（"shorten to X"）；组内 [N] 项 = 名称 + 现状 + 做法 + (Owner: 角色) |
| 4 | Next Steps | "Upon approval" 批准后行动 + "Subject to X's decision" 条件行动 + 治理节奏（时间盒高频跟踪 → 降频） |
| 5 | The End | 显式终止符，杜绝"后面还有吗"的歧义 |
| A | Appendix | 五类附页：流程图 / 解-题映射表 / RACI 检查表 / SLA 表 + 数据溯源表（全局必配，见 L2 数据溯源铁律） |

**编号约定**：问题用 (a)(b)(c)，方案与行动用 [1][2][3]——两套编号在附页解-题映射表中交叉引用，追溯性由编号体系承载。

**该分叉专属规则**：

1. **单方案推荐**：直接给一个推荐方案，不列选项对比（Amazon 传统）；反方质疑由附页（FAQ / 解-题映射）接住，不用选项表替代论证。
2. **决策旗标**：正文显式标注决策权（"seek X's final decision" / "Subject to X's final decision"），读者一眼知道谁拍板、哪些事项待拍板。
3. **Owner 标签**：每个优化项/行动项括号标注 (Owner: 角色)，写角色不写人名（BD / PM / Finance）。
4. **解-题映射表**：附页放 [方案]×[问题] 追溯矩阵；映射不到任何问题的方案删除（So What 测试的结构化形态）。
5. **治理节奏**：Next Steps 写明跟踪频率与降频计划（"前 2 个月月度 → 之后季度"），与标题限定词 (Pilot) 配套——提案自带退出机制。
6. **RACI 检查表**：行动项 >5 条时，附页放 Phase / Item / Activities / Accountable / Deadline / Meet Target 六列表。
7. **数据带锚点**：正文数据按 L2 数据溯源铁律带 (D#) 锚点，来源信息完整落附页溯源表（如样例 "Based on existing YTQ (Q3) application, there are 8 deals pending…" 的做法），无来源的数据不进正文。

### 5.5 学习复述分叉 · Book Memo 房屋模式

> 蒸馏自 Mortimer Adler《How to Read a Book》分析阅读规则 × Derek Sivers 书目备忘录实践（sive.rs/book）× 费曼复述测试。学习复述分叉（书籍/长文/课程压成一页）默认采用此骨架。核心立场（Sivers）："书摘是 punchline，不是 summary"——一页纸不还原书，是个人化提取；复述的价值锚点是惊讶点，不是覆盖度。

**七段式骨架与公式**：

| # | 段落 | 公式 | 源 |
|---|---|---|---|
| 0 | 标题行 | 书名 + 作者 + 读完日期 + 推荐分（0-10，"随机 10 人中几人该读"） | Sivers |
| 1 | 一句话定位 | 书的分类（理论/实践）+ 整本书一句话概括（"这是一本关于___的书"） | Adler 规则 1-2 |
| 2 | 作者的问题 | 作者试图回答什么问题；哪些回答了、哪些没有（≤2 句） | Adler 规则 4/8 |
| 3 | 骨架 X 光 | 全书主要部分及其顺序与关系，金字塔归纳重排 | Adler 规则 3 × Minto |
| 4 | 术语表 | 作者重新定义的关键词 ≤5 个，一行一词一义 | Adler 规则 5 |
| 5 | 惊讶点 | 反直觉/高价值提取 3-7 条，压缩成指令式短句 | Sivers |
| 6 | What of it | 读完改变什么行动或信念；与既有认知的冲突点 | Adler 第三阶段 |
| A | Appendix | 论据地图（哪章支撑哪个结论）+ 数据溯源表（书中数据记页码）+ 金句 ≤3 条（装饰锚点） | 本文件 |

**该分叉专属规则**：

1. **Punchline 化改写**：提取的要点必须用自己的语言压缩成指令式短句，禁止摘抄原文段落充数（Sivers 编辑纪律：笔记是给自己用的提取，不是书的压缩包）。
2. **目录禁令**：骨架 X 光照抄目录 = 摘要不是浓缩（同 5.1 Step 3）；原文结构服务于原文篇幅，一页纸结构服务于复述。
3. **费曼复述测试**（该分叉专属质检，并入 Q1 执行）：不使用书中行话，向没读过书的人 60 秒讲清核心论点——讲不出回骨架 X 光重做。
4. **覆盖率自检**：一页纸只需承载"惊讶点 + 骨架"，完整性交给附页论据地图；不为覆盖度牺牲惊讶点。
5. **评分为锚**：推荐分写明一句话理由——它暴露你与书的关系，不是书的客观属性。

### 5.6 信服洞察分叉 · Insight Page 房屋模式

> 蒸馏自 Gene Zelazny《Say It With Charts》（麦肯锡可视化总监）message title + 五比较图型 × FT 数据新闻"Chart that explains"式标注语法。信服洞察分叉（调研报告/数据分析压成一页）默认采用此骨架。核心立场（Zelazny）：图不是数据的容器，是论证的载体——"读者永远不该看完图问 So What"。

**七段式骨架与公式**：

| # | 段落 | 公式 | 源 |
|---|---|---|---|
| 0 | 标题行 | Action Title 即结论，反直觉表述（"是 X 导致了 Y，而非 Z"） | Zelazny / MBB |
| 1 | 结论块 | 主张一句话 + 置信度 + 样本/数据基础（回答"凭什么信"） | 本文件 |
| 2 | SCQ 压缩开场 | S、C 各 ≤2 句：为什么这个结论反直觉、为什么现在重要 | Minto |
| 3 | 主图 | 一图一结论：图承担叙事主体；图题写结论不写指标名 | Zelazny |
| 4 | 图上直标 | 转折点/异常值/干预事件直接标注在图上；系列直标，不用图例切换 | FT |
| 5 | 反方预案 | 最强替代解释 1-3 条 + 排除逻辑（"另一种解释是 A，但被 B 排除"） | Amazon FAQ |
| 6 | So What | 接受结论后的行动含义，带 Owner 与时限 | MBB |
| A | Appendix | 方法论/样本/数据字典 + 数据溯源表 + 支撑图表组 | 本文件 |

**选图速查**（Zelazny 三步：先写出信息 → 定比较类型 → 机械选图型）：

| 比较类型 | 触发词 | 图型 |
|---|---|---|
| 成分（占整体比例） | 占比、占…% | 饼图 / 100% 堆叠条 |
| 排序（项与项比） | 排名、高于/低于 | 条形图 |
| 时间序列 | 趋势、增长、逐月 | 折线 / 柱状 |
| 分布（区间频次） | 分布、集中于 | 直方图 / 阶梯折线 |
| 相关（两变量关系） | 随…上升、相关 | 散点 / 成对条 |

**该分叉专属规则**：

1. **一图一结论**：主图至多 1 张；需要多图 = 多个结论 = 拆页，或把次图降级附页。
2. **图题写结论**："各地区销售额"是废题，"三区以新品增长跑赢所有大区"是结论题。
3. **直标不用图例**：标签贴在数据末端/近旁，读者视线不往返（FT direct labeling）。
4. **基线服务于论证**：坐标起点、线性/对数、参照线的选择必须服务主张，并在图注声明（FT 基线纪律）。
5. **数据代形容词最严档**：该分叉 weasel words 零容忍（Q4 按最严标准执行）。

## 6 · 质检门（交付前必过，任何一条不过即回炉）

按顺序执行，全部通过才允许进入视觉层（style-system.md）：

| # | 测试 | 方法 | 出处 |
|---|---|---|---|
| Q1 | 电梯测试 | 只读首段，能否 30 秒复述主张；学习复述分叉加严为费曼变体：不用书中行话 60 秒讲清核心论点 | 麦肯锡 / 费曼学习法 |
| Q2 | 水平逻辑测试 | Action Title 场景：标题串读成完整连贯摘要，串不起来 = 标题是主题不是结论；功能性标题场景（决策行动）：改测 Purpose 首段——首段须独立承载决策请求 + 量化目标 + 理由 | 麦肯锡 / Amazon |
| Q3 | So What 测试 | 逐段问"所以呢"，回答不上或答案是"没所以"的段落删除 | 麦肯锡 |
| Q4 | Weasel 扫描 | 按第 3 节禁用词表全文检索，命中即改 | AWS |
| Q5 | 数据替换扫描 | 全文检索形容词，凡可量化未量化即改 | AWS |
| Q6 | MECE 复核 | 同层信息组有无重叠、有无遗漏；条数是否 3-7 | Minto / AWS |
| Q7 | 反方测试 | 附页 FAQ 能否接住最挑剔读者；接不住的回 0→1 协议 Step 3 补课 | AWS |
| Q8 | 一页约束 | 正文（不含附页）不溢出画布；溢出先删内容，禁止缩字号硬塞 | 亚马逊篇幅纪律 |
| Q9 | 数据溯源测试 | 正文每个数据有 (D#) 锚点且溯源表有对应行；表行均在正文被引用；无无源数据伪装有源；抽任一数字模拟 3 分钟 crosscheck | Amazon 证据纪律 + 用户规范 |

## 7 · 与视觉层的交接

叙事层产出并过完质检门后，交接给 style-system.md 的最小契约：

1. 一句话主张 + SCQ 开场 + 3-7 个结论式标题的信息组 + 附页证据包（必含数据溯源表）。
2. 信息组数量即视觉层骨架选型输入（如 3 组对照宜 S5 分屏、多组并列宜 S1/S6、数据主体宜 S7）。
3. 浓缩目标（学习复述/决策行动/信服洞察）映射叙事模板（读薄型/汇报型/洞察型），再映射视觉密度（R8）。
