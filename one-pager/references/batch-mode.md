# Batch Mode — 批量输入的分级产出（借鉴 Amazon 6-pager）

**触发（唯一定义，SKILL.md 与 input-protocol.md 同此口径）**：单一来源 ≥5 万字（一本书、一份长报告），**或多文件合计 ≥5 万字**。多文件但合计不足 5 万字走普通 100→1 浓缩。一页纸对这类输入仍然成立（N0 不变），但在它和证据附页之间，插入一层六页叙事稿。

> 术语：本文件的 **N0/N1/N2 指产出三级**（一页纸/六页叙事稿/附页）。style-system.md 的 **T1–T7 指视觉预捆模板**。两套编号互不相干。

**为什么借鉴 6-pager**：把一本书压到 700 字，损失是功能不是缺陷——但当读者的下一动作不止"3 分钟抓结论"（读书会要讲 10 分钟、团队要照书重构流程）时，一页纸装不下。Amazon 对同类问题的解法是 6-pager：**正文硬上限 6 页约束论证，附录不限释放证据，完整句子叙事，为无声阅读而写**（读者没有讲解者在场，文档必须自足）。批量模式把这套原则嫁接到 one-pager 架构上。

## 三级结构

| 层 | 载体 | 长度 | 纪律 |
|---|---|---|---|
| N0 一页纸 | `.page` | 1 页 | 全部现行规则不变：三叉路由、Q1-Q9、humanize、(D#) 锚点 |
| N1 六页叙事稿 | `.narrative` | 正文 ≤6 页 | 见下方六页稿纪律 |
| N2 附页 | `.appendix` | 不限页 | 现行机制：溯源表、论据地图、金句、未尽事项 |

N0 是主张与入口，N1 是论证主体，N2 是证据。读者按需下潜：30 秒拿结论读 N0，10 分钟听懂读 N1，核查证据进 N2。

## N1 骨架（按分叉适配）

学习复述（书 / 长文）：

1. 引言：本稿是什么、主张一句话、**蒸馏深度声明**（哪些章精读、哪些按作者小结蒸馏）
2. 作者与主张：作者的问题、凭据、立场
3. 全书骨架：结构的叙事版（归纳重排，非目录复述）
4. 分部叙事：每部分 / 每章一段完整句浓缩（带 D# 锚点）
5. 评析与开放问题：书的强处、作者承认的未决问题
6. 应用与指针：What of it 展开 + 附页指针

决策行动（多文档 / 长报告）：用经典 6-pager 结构——引言 → 目标与信条 → 现状 → 经验教训 → 提案 → 附页指针；内容按 Proposal 五段式的分叉规则填充（决策旗标、Owner 标签、行内编号照旧）。

信服洞察：结论块 → SCQ → 证据叙事 → 反方预案 → So What（图表按 Zelazny 纪律，一图一结论）。

## 六页稿纪律（从 Amazon 6-pager 借来的硬规则）

- **正文 ≤6 页**：与一页约束同源的预算压力。超了先归并再删内容，不动版式字号（同 R1 精神）。6 页是上限不是目标——不为凑页数注水，宁短勿滥。
- **完整句子**：论证段落禁 bullet（同一页纸 L3 规则）；真结构枚举可保留。
- **无声阅读生存**：假设讲解者不在场，每段自足。这是 6-pager 会议前 15 分钟静默阅读的写作要求，也是 N1 与"讲稿"的分界。
- **15 分钟阅读量**：中文约 6000-9000 字封顶。
- **数据最小单元 + 锚点连续**：正文只留支撑结论的最小数字；D# 与 N0 连续编号，共用同一张溯源表。
- **蒸馏深度标注**：论据地图标注每章蒸馏深度（精读 / 作者小结 / 目录级）——诚实优于装懂，读者有权知道哪段是几手信息。扫描方法本身见 `references/input-protocol.md` 的 navigation-first 80/20。
- **humanize 同样适用**：N1 是正文类文本，过同一份 humanize 清单（`references/humanize.md`）。

## 衔接与声明

- 输出开头的声明加一行：`MODE: batch · N0 one-pager + N1 six-page narrative + N2 appendix`
- N1 视觉：用模板的 `.narrative` 块，复用全局样式（正文 13.5px 落在 R3 区间），accent 与 N0 一致——同一份文件，不换皮肤，不引入新排版决策。
- Phase 2 验证：N0 的 `.page` 仍须 1123px 不溢出（R1 原样执行）；N1 只查页数预算（≤6）。
- Phase 3 验证 PDF 页数：1（N0）+ ≤6（N1）+ 附页页数。
